# SDLC Document Access — slice, don't slurp

The SDLC specs under `docs/` (notably `docs/PRD.yaml`, `docs/DATA-MODEL.yaml`,
`docs/TASKS.json` and the large `ARCH__*` / `TASKS__*` shards) grow large enough
that loading one whole burns a big slice of an agent's context window. They are
consumed by agents with limited context, so retrieve only the structure plus the
minimum relevant slice. `Read` with `offset`/`limit` loads **only** the
requested lines — the file's total size is irrelevant once you know the range.

## The entrypoint: `docs/INDEX.yaml`

A **generated** location map **plus a cross-reference graph** — never hand-edit
it. It is regenerated by the `Write|Edit|MultiEdit` PostToolUse hook on every
canonical `docs/*.yaml`, `docs/TASKS*.json` **or `docs/*__*` shard** edit (or by
running `python .claude/sdlc/docs_index.py`). It contains these blocks:

- `generated_from` — per-file `sha256` prefix + line count for **every indexed
  file, canonicals and shards alike**. The hash is the one canonical content
  hash (see "The content hash" below); a consumer skill copies it into its
  `metadata.upstream_provenance` instead of hashing on its own.
- `sections` — for each **canonical** doc (YAML **and** the JSON canonicals
  `TASKS.json` / `CODE-MANIFEST.json`), every top-level key → `[start, end]`
  line range. Shards are deliberately not sectioned; their content is reached
  through `symbols` or loaded whole when small.
- `shards` — every `docs/<PARENT>__<slug>.yaml|json` sub-artifact present,
  keyed by its parent canonical (`UX.yaml: [UX__login.yaml, …]`). Use it to
  *discover* which per-surface/container/resource files exist.
- `symbols` — **grouped by file**; each addressable symbol is one positional row:
  `name: [start, end, kind, context, summary]` (`context` is `~` when none). The
  owning file is the group header the row sits under — read the first two numbers
  as the `[start, end]` line range. Symbols cover:
  - DATA-MODEL `entities` (by name) + `enums`;
  - PRD `FR-###` items and every other single-namespace id family
    (`NFR/WKF/ENT/INT/AIF/OOS/PER/GOL/PAN/JTB/EDG/ACR`), `USR-###` user stories,
    each `conventions.*` sub-block (kind `convention`);
  - UX `SCR-###` surfaces;
  - **ARCH__<cid> shards**: each `component_id` (kind `component`) and each work
    unit keyed **`<cid>/<component>/<unit>`** (kind `work_unit`) — the address
    sdlc-task / sdlc-code use;
  - **TEST-STRATEGY** (+ `__<cid>` shards): every `tst_id` (`TST-###`, or the
    container-prefixed `TST-<PREFIX>-###`);
  - **API__ shards**: `OPR-###` operations; **DESIGN__assets**: `AST-###`;
  - canonical `TASKS.json` `TSK-###` tasks (bare id), and every
    `TASKS__<cid>.json` shard's tasks keyed by **qualified id** `<cid>/TSK-NNN`.
- `referenced_by` — the **inbound edge map** (edit blast-radius): for each defined
  id **or named symbol (entity, enum, component, work unit, task)**, the
  symbols / sections / tasks that mention it, grouped by the doc that DEFINES it.
  A shard's section container reads `<file>:<section>`; symbol containers are
  bare names. `WRN-###` rows are file-local (a warning id belongs to the file
  that lists it). Consult this before editing a symbol so you reconcile every
  inbound site in the same pass.
- `dangling` — references whose id is a **blocking** corpus family
  (`FR/NFR/ENT/WKF/SCR/USR/…`) but resolves to no definition (a typo or a deleted
  symbol). `dangling: []` is the clean state; `docs_index.py --check` exits
  non-zero when it is non-empty. **Only a structured reference counts** — the
  whole value of a field, a list entry, or a flow-list element (`covers:
  [FR-001]`, `- FR-001`, `refs: [QUE-004]`). An id inside prose (a description
  that illustrates the id format, an example locator such as
  `operations[OPR-014]`, a warning that mentions one) is a mention: it still
  feeds `referenced_by` when it resolves, but it is never dangling.
- `dangling_warnings` — unresolved structured references that do **not** fail
  `--check` yet: the `TST/OPR/AST/QUE` families (warn-first for one version)
  and named references (`touches_entities`, `via_unit`, `target_symbol`,
  `component_ref`, `depends_on`, …) whose name no artifact defines. Treat them
  as defects to fix, not noise.
- `warnings` — files the generator could not read or parse (a shard that is not
  valid JSON is skipped, not fatal) and symbol-name collisions.
- `retired_ids` — ids deliberately cited without a definition (see "Retired
  ids" below); present only when non-empty.

`INDEX.yaml` duplicates no field bodies; `summary` is a ≤120-char hint only. The
canonical truth always lives in the source file — resolve there before relying
on it.

## Retrieval protocol

1. **Never read `PRD.yaml`, `DATA-MODEL.yaml`, `TASKS.json`, or a large
   `ARCH__*` / `TASKS__*` shard in full.** Load `docs/INDEX.yaml` first.
2. **Resolve by symbol, read by range.** Look the name up in `symbols`, then
   `Read(file, offset=start, limit=end-start+1)`. Use `summary` to pick the right
   symbol without opening several.
3. **Resolve a top-level block by its `sections` range.** To read one block of a
   doc (e.g. PRD `conventions`, DATA-MODEL `cross_references`), slice the
   `[start, end]` range listed under `sections.<file>.<key>` — don't load the file
   whole to find it.
4. **Follow cross-references lazily.** Only resolve a linked entity when the task
   needs its fields. To traverse relationships, slice the `composition` /
   `cross_references` sections (via their `sections` ranges) — do not load
   `entities` whole to find a link.
5. **Never inline large repeated blocks** into prompts or other artifacts; reference
   a symbol by name + range.
6. **Self-heal a stale range.** If a sliced range does not begin with the expected
   `<name>:` anchor, the index lagged an edit: relocate with `Grep`
   (`^\s*<name>:` for entities/enums; `"<FR-id>:` for an FR; `- name: <unit>` for
   a work unit; `- tst_id: <id>` for a test), `Read`, then regenerate with
   `python .claude/sdlc/docs_index.py`.

## Power tools

`python .claude/sdlc/docs_index.py <cmd>`:

- `--show <symbol>` prints exactly one symbol's slice. `<symbol>` is any bare id
  of any family (`FR-001`, `NFR-003`, `WKF-002`, `SCR-001`, `USR-001`, `ENT-004`,
  `TST-012`, `TST-CLI-012`, `OPR-001`, `AST-001`), an entity / enum name, a
  `conventions.*` block key, a component id, a work unit (`<cid>/<component>/
  <unit>`, or just `<unit>` when that name is unique — an ambiguous bare name
  lists the candidates), a canonical `TSK-###`, or a shard task's qualified id
  `<cid>/TSK-NNN`. The cheapest way to pull one task or one work unit out of a
  large shard.
- `--refs <symbol>` prints a symbol/id's **blast-radius**: the ids it references,
  the containers that reference it (`referenced_by`), and any dangling references
  inside it. It answers for **entities** (`--refs User` → every work unit, task,
  edge and API resource that touches it), **work units** (`--refs create_user`
  → the tests targeting it, the task implementing it, the edges calling it) and
  **tests** (`--refs TST-012` → the task realizing it). **Run this before
  editing, renaming or dropping a symbol** so you reconcile every inbound site
  in the same pass.
- `--check` rebuilds the index and **exits non-zero if any blocking reference is
  dangling** — the id-integrity gate for a pre-commit / CI hook. Warn-first
  families, unresolved names and index warnings print under `WARNINGS` and do
  not change the exit code. (The PostToolUse hook path stays non-blocking.)
- `--find kind=… context=… file=… text=… references=… referenced_by=…` is a
  predicate search over the symbol table (AND semantics) — e.g.
  `--find kind=work_unit context=users-service` or `--find references=FR-001`.
- `--hash <file>` prints the canonical 16-hex content hash of a file (the same
  value `generated_from` records). Use it when you need a provenance hash for a
  file the index does not cover; never hash inline.
- `--drift <artifact>` reads the artifact's `metadata.upstream_provenance`,
  compares every recorded hash with the upstream's current hash, and for each
  upstream that moved names what changed. When the stamp carries an `items`
  map (written by `--stamp`), the delta is exact and item by item: which work
  units / tests / entities / requirement items were **added**, **removed** or
  **changed in body** since the artifact was written — no git, no guessing.
  Without one it falls back to the artifact's own references as the old set,
  subtracts the artifact's structured `deferrals`, and says plainly that the
  residue mixes "new upstream" with "never covered". Exit 0 = built against
  the current upstreams, 1 = at least one moved, 2 = cannot read. Under each
  moved upstream a `why` line quotes that upstream's own changelog entries
  since the stamp — the reason for the change, written by whoever made it.
  Every consumer skill calls it in Phase 2 before deciding whether an
  upstream-change review is due; it never edits anything.
- `--stale [--json]` runs the same comparison over every artifact at once and
  lists the stale ones **in the order to reconcile them** (upstream first, a
  system file before its shards), each with its owning skill's `--reconcile`
  command. A `--reconcile` run computes its `Next:` from it, which is what
  lets the chain after a repair route itself. Exit 1 when any file is stale.
- `--items <upstream>` prints every item the upstream defines with its body
  hash — what `--stamp` records. A work unit's hash ignores its
  declaration-only fields (`touches_entities`, `status`), so an entity-trace
  backfill is not a change; only behaviour-bearing fields are. `--json` for a
  mapping.
- `--stamp <artifact> [--upstream docs/<file> ...]` rewrites the artifact's
  `metadata.upstream_provenance`: `{file, session_id, last_updated, version,
  sha256, items}` per upstream — the ones already recorded plus every `--upstream`.
  It writes ONLY that artifact (never the index, never an upstream), so it is
  safe on a project that runs its own index generator. Every skill that writes
  an artifact runs it at write time instead of hand-writing the entries.

**No installed copy?** A project that generates `docs/INDEX.yaml` with its own
tool has no `.claude/sdlc/docs_index.py`. The read-only subcommands (`--drift`,
`--stale`, `--items`, `--hash`, `--show`, `--refs`, `--find`, `--check`) and `--stamp`
(which writes only the artifact it is given) may then be run from the plugin's
own copy, `python "${CLAUDE_SKILL_DIR}/../setup/docs_index.py" --docs-dir docs …`
— never the bare form, which would regenerate `docs/INDEX.yaml` over the
project's own.

## The content hash

`generated_from[<file>].sha256`, `--hash`, and every `metadata.upstream_provenance[].sha256`
are the same value:

    sha256(path.read_text(encoding="utf-8").encode("utf-8")).hexdigest()[:16]

Text-level on purpose — `read_text` normalises line endings, so a CRLF checkout
and an LF checkout hash the same and provenance does not go stale when a file is
merely re-saved on another OS. Read the hash from `INDEX.yaml` or call `--hash`;
do not compute `sha256(bytes)` yourself — it differs on CRLF.

## Retired ids

A changelog legitimately cites an id that no longer exists; the reference scan
skips `metadata.changelog` for exactly that reason (and only that block —
`*_warnings` notes are real inbound sites). When a retired id is cited
elsewhere on purpose (a deferral note, a migration comment), declare it once
instead of deleting history:

- `docs/INDEX.allow.yaml` (hand-maintained, never generated):

      retired_ids:
        - id: FR-058
          reason: "merged into FR-001 in 1.1"

- or the PRD's `metadata.retired_ids: [{id, reason}]`.

Both channels merge; a retired id is neither an edge nor dangling and is listed
under `retired_ids` in the index.

## Maintaining the index

- `INDEX.yaml` is a derived artifact — edit the canonical source; the hook refreshes it.
- The generator (`.claude/sdlc/docs_index.py`) content-*sections* the canonical
  docs only, but **scans every shard** (`UX__*`, `ARCH__*`, `API__*`,
  `DESIGN__*`, `TEST-STRATEGY__*`, `TASKS__*`) for definitions and references,
  records each in `generated_from`, and symbol-indexes the addressable items
  inside them. Versioned snapshots and `*_draft` files are ignored.
- Do **not** split `PRD.yaml` / `DATA-MODEL.yaml` / `TASKS.json`: range-based
  slicing already gives free partial reads, and the `entities` graph
  (`composition`, `cross_references`) is a whole-file relation that splitting
  would fragment. (UX/ARCH/API/TEST/TASKS are sharded because their
  surfaces/containers/resources are independent documents.)
